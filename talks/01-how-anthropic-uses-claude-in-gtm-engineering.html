How Anthropic uses Claude in GTM Engineering

ผู้พูด: Jared Sires (GTM Product Manager ที่ Anthropic (ตามคำอธิบายคลิป; ในเสียงพูดแนะนำแค่ชื่อ Jared และบอกว่าตัวเองเป็น go-to-market architect))

เหมาะกับ: ทีมขายหรือ GTM ที่อยากรู้ว่าคนไม่ใช่สายเทคนิคสร้างเครื่องมือภายในเองด้วย Claude ได้แค่ไหน ไม่ต้องมีพื้นฐานโค้ด

Jared เล่าว่าตอนเป็น account executive ต้องดูแลลูกค้า 600-700 บัญชี ตอบอีเมลถึงสองสามทุ่มทุกวัน เลยสร้างเครื่องมือชื่อ Class (Claude Draft) ที่ใช้ Claude API ร่างอีเมลตอบลูกค้าให้ ผู้พูดบอกว่าประหยัดเวลาได้อย่างน้อย 2-3 ชั่วโมงต่อวัน และทำให้ย้ายสายงานมาเป็น go-to-market architect ได้

A former account executive with no coding background built Class (Claude Draft), a Claude API tool that drafts customer email replies from internal context. He says it saves 2-3 hours a day and changed his career.

ประเด็นสำคัญ

  1. ผู้พูดเริ่มจากปัญหาจริง ตอนเป็น startup AE ดูแลราว 600-700 บัญชี ต้องค้น Slack, knowledge base, Google Docs, Google Drive แล้วตอบอีเมลจนถึง 2-3 ทุ่ม
  2. คำถามตั้งต้นคือ จะดึง Claude เข้ามาอยู่ใน loop ได้อย่างไร จึงพัฒนา Class ซึ่งย่อมาจาก Claude Draft
  3. Class จัดการ inbox โดยต่อกับ context knowledge, system prompt และ pattern matching
  4. ขั้นแรกคือสร้าง system prompt ใส่ชื่อ ตำแหน่ง (เลือกจาก drop-down เช่น account executive) และสิ่งที่ช่วยลูกค้า แล้วกด generate prompt เบื้องหลังใช้ Claude API
  5. ขั้นต่อมาคือดึง context ผ่าน integration กับ Google Docs และดึง URL เว็บได้ด้วย เช่นหน้า doc ของ Claude แล้วเปิดอีเมลกด generate draft
  6. Claude ไปดึงข้อมูลจากเว็บไซต์ เอกสาร และ context ภายใน ทำให้ตอบลูกค้าเชิงเทคนิคได้ โดยไม่ต้องไล่หาใน Slack หรือ Google Docs เอง
  7. ผู้พูดบอกว่าประหยัดเวลาอย่างน้อย 2-3 ชั่วโมงต่อวัน และมีอีเมลหลายพันฉบับที่ส่งผ่านระบบนี้
  8. พอกำแพงทางเทคนิคลดลง เขาออกแบบผลิตภัณฑ์ได้มากขึ้นแล้วให้ senior engineer ช่วยปิดท้าย และย้ายมาเป็น go-to-market architect

ลำดับขั้นที่ทำในคลิป

  1. เปิด Class แล้วสร้าง system prompt: ใส่ชื่อ เลือกตำแหน่งจาก drop-down (account executive) ใส่สิ่งที่ช่วยลูกค้า แล้วกด generate prompt
  2. ตั้งค่า context retrieval ผ่าน integration กับ Google Docs (ดึง URL เว็บได้ด้วย) แล้วเพิ่ม doc
  3. เปิดอีเมลที่ต้องตอบ แล้วกด generate draft
  4. Claude ดึงข้อมูลจากเว็บไซต์ เอกสาร และ context ภายใน มาร่างคำตอบ

ตัวเลข / ข้อเท็จจริงที่ผู้พูดบอก

ตามที่ผู้พูดอ้างในคลิป ไม่ได้ยืนยันกับแหล่งอื่น

  • ดูแลบัญชีลูกค้าประมาณ 600-700 บัญชีตอนท้ายๆ ที่เป็น startup AE
  • ทำงานถึงประมาณ 2-3 ทุ่ม (8:00-9:00 pm) เพื่อตอบอีเมล
  • ประหยัดเวลาอย่างน้อย 2-3 ชั่วโมงต่อวัน (ผู้พูดประเมินเอง)
  • มีอีเมล "หลายพันฉบับ" ที่ส่งผ่านระบบ Class (ผู้พูดบอก ไม่ได้ให้ตัวเลขแน่ชัด)

ประโยคเด่น (ต้นฉบับ)

“I would say Class is saving probably me at least 2-3 hours a day for answering emails”

Class ช่วยประหยัดเวลาตอบอีเมลอย่างน้อย 2-3 ชั่วโมงต่อวัน

“I don't have to go over Slack. I don't have to go over Google Docs to figure out how I need to respond.”

ไม่ต้องไล่หาใน Slack หรือ Google Docs เพื่อรู้ว่าจะตอบอย่างไร

“I feel like with the technical barrier dissolving, I'm almost able to design more products and have senior engineers help me implement this to the final”

พอกำแพงเทคนิคหายไป เขาออกแบบผลิตภัณฑ์ได้มากขึ้นและให้ senior engineer ช่วยทำช่วงสุดท้าย

สิ่งที่นำไปทำต่อ

  • เริ่มจากงานที่กินเวลาจริงของตัวเอง (ตอบอีเมลซ้ำๆ) แล้วถามว่าจะเอา Claude เข้ามาใน loop ตรงไหน
  • เครื่องมือแบบนี้มีแค่สามส่วน คือ system prompt ที่บอกบทบาท, แหล่ง context (Docs, เว็บ), และ pattern matching กับอีเมลที่เข้ามา
  • คนสายขายสร้างต้นแบบเองได้ แล้วให้ senior engineer ช่วยปิดงานช่วงท้าย ไม่ต้องรอทีม engineering ตั้งแต่ต้น
  • ให้เอกสารและความรู้ภายในอยู่ในจุดที่ Claude เข้าถึงได้ จะได้ไม่ต้องไล่หาข้ามหลายระบบทุกครั้ง
