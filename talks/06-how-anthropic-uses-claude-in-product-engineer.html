วิศวกร backend ใช้ Claude Code + Playwright MCP ทำ Excel renderer บนฝั่ง frontend

How Anthropic uses Claude in Product Engineering

ผู้พูด: Chuma Kabaghe (Software Engineer ที่ Anthropic (ตามคำอธิบายคลิป))

เหมาะกับ: วิศวกรที่ต้องเข้า codebase ใหม่หรือข้ามสาย backend/frontend รู้จัก Claude Code และ MCP ระดับพื้นฐานก็พอ

Chuma Kabaghe เป็น backend engineer ที่ใช้ Claude Code ทำความเข้าใจ codebase frontend ที่ไม่คุ้น แล้วต่อ Playwright MCP ให้ Claude เปิดแอปดูผล แก้ และวนทดสอบเอง เดโมทำฟีเจอร์ preview ไฟล์ Excel, CSV, TSV ใน Claude.ai เธอบอกว่าเวลาที่เหลือเอาไปคิดระดับระบบและ trade-off มากขึ้น

A backend engineer uses Claude Code plus the Playwright MCP to onboard onto a frontend codebase and build an Excel preview feature in an autonomous edit-and-verify loop.

ประเด็นสำคัญ

  1. ผู้พูดเปรียบ Claude Code เป็นเหมือนส่ง sidekick ไปหาข้อมูล แล้วกลับมารายงาน
  2. ตอนเข้า Anthropic ทีมทำ code execution และ file generation ใน Claude.ai (ให้ Claude มีคอมพิวเตอร์และสร้างไฟล์ รวมถึง Excel) มี deadline ประมาณหนึ่งเดือนครึ่ง
  3. เธอเป็น backend engineer แต่งานนี้เป็น frontend ปกติ onboard ใช้เวลานาน ใช้ Claude Code วางพื้นฐานใน codebase ได้เร็วกว่า
  4. จุดที่เธอว่าเจ๋งสุดคือการต่อ Claude Code กับ Playwright MCP
  5. เดโม: ให้อ่าน EXCEL_RENDERER_DESIGN.md (design doc/spec) แล้วทำฟีเจอร์ preview Excel, CSV, TSV ด้วย Playwright MCP โดย Claude เปิดแอปดูสภาพก่อนทำ แล้วขออนุญาตแก้ไฟล์
  6. หลังอนุญาต Claude วนลูปกับ Playwright แก้ ตรวจ และวนต่อ จนได้สรุปการเปลี่ยนแปลงให้รีวิวโค้ด
  7. ผู้พูดยังได้เขียนโค้ดและสร้างของอยู่ แต่มีเวลาคิดภาพรวมระบบ กลยุทธ์ trade-off การเชื่อมกับทีมอื่น และงานด้านคน
  8. Claude Code ทำให้เธอฝันใหญ่ขึ้น เพราะไม่ถูกจำกัดด้วยภาษาที่ถนัดอีกต่อไป

ลำดับขั้นที่ทำในคลิป

  1. ใส่ prompt: ให้ implement ฟีเจอร์ Excel renderer สำหรับ Claude.ai อ่าน EXCEL_RENDERER_DESIGN.md และใช้ Playwright MCP โดยฟีเจอร์ต้อง preview Excel, CSV, TSV ได้
  2. Claude Code อ่าน codebase และสตาร์ตแอป Claude.ai ผ่าน Playwright MCP เพื่อดูสภาพก่อนทำฟีเจอร์
  3. Claude ขออนุญาตแก้ไฟล์ ผู้พูดกดอนุญาต
  4. Claude วนลูปกับ Playwright: แก้โค้ด ตรวจผล ปรับต่อ
  5. ได้สรุปการเปลี่ยนแปลงทั้งหมด พร้อมให้ผู้พูดรีวิวโค้ด

ตัวเลข / ข้อเท็จจริงที่ผู้พูดบอก

ตามที่ผู้พูดอ้างในคลิป ไม่ได้ยืนยันกับแหล่งอื่น

  • deadline ที่ทีมตั้งไว้สำหรับฟีเจอร์ code execution และ file generation: ราวหนึ่งเดือนครึ่ง
  • ไฟล์ที่ฟีเจอร์ preview รองรับในเดโม: Excel, CSV, TSV
  • ไฟล์ design doc ในเดโมชื่อ EXCEL_RENDERER_DESIGN.md

สิ่งที่นำไปทำต่อ

  • ให้ Claude Code อ่าน codebase ที่ไม่คุ้นก่อนลงมือ เป็นวิธี onboard ที่เร็วกว่าอ่านเอง
  • เขียน design doc/spec แล้วชี้ให้ Claude อ่านใน prompt
  • ต่อ Playwright MCP ให้ Claude เห็นผลลัพธ์จริงของ UI และตรวจงานตัวเองเป็นลูป
  • ยังต้องรีวิวโค้ดที่ได้เอง แล้วใช้เวลาที่เหลือกับการตัดสินใจระดับสูง

  • ไม่ได้บอกตัวเลขผลลัพธ์เชิงปริมาณว่าเร็วขึ้นเท่าไร และไม่ได้ยืนยันว่าส่งฟีเจอร์ทันกำหนด
  • ไม่ได้พูดถึงโมเดลหรือเวอร์ชันที่ใช้
