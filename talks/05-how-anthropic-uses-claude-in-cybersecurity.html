ทีม security ใช้ Claude Code สร้าง CLUE ให้ triage alert เหลือเป็นนาที

How Anthropic uses Claude in Cybersecurity

ผู้พูด: Jackie Bow (Technical Lead, Detection Platform Engineering team ที่ Anthropic (ตามคำอธิบายคลิป))

เหมาะกับ: ทีม security operations / detection engineering ที่จมอยู่กับ alert และสลับหลายเครื่องมือ ไม่ต้องมีพื้นฐาน Claude Code มาก่อน

ทีม detection ของ Anthropic สร้าง CLUE แพลตฟอร์ม detection and response ด้วย Claude Code ที่ต่อกับ data warehouse, Slack และ code base ภายใน ให้ Claude วางแผนสืบสวน alert แล้วยิง query เอง ผู้พูดบอกว่างานที่เคยใช้หลายชั่วโมงถึงหลายวันเหลือเป็นนาที และ Claude Code ช่วยให้คนใหม่ทำ suppression engine เสร็จในสัปดาห์เดียว

Anthropic's detection team built CLUE with Claude Code: an investigation platform wired to internal data, Slack and code that plans and runs alert investigations, and surfaces only what a human needs to review.

ประเด็นสำคัญ

  1. ผู้พูดบอกว่าก่อนมี CLUE การสืบสวน security event ต้องสลับ 5-6 เครื่องมือ รัน query 3-4 ภาษาบนหลายฐานข้อมูล แค่เคสง่ายก็ใช้เวลาอย่างน้อยสองสามชั่วโมง นานสุดสองสามวัน
  2. CLUE เป็นแพลตฟอร์ม detection and response ที่สร้างด้วย Claude Code ต่อกับระบบภายในผ่าน tool use เพื่อ query data warehouse ได้
  3. นอกจากข้อมูลเชิงเทคนิค ยังค้นความรู้ภายในบริษัทได้ด้วย ทั้ง Slack message และ code base ซึ่งผู้พูดเรียกว่าชิ้นที่ขาดไป ทำให้ alert มี context ของสภาพแวดล้อมจริง
  4. เดโมใช้ข้อมูลตัวอย่าง ไม่ใช่ข้อมูลภายในจริง: ถามว่า developer ให้สิทธิ์ admin ตัวเอง ได้รับอนุญาตไหม มี credential compromise ไหม และทำอะไรต่อบ้าง Claude ร่างแผนสืบสวน 6 ขั้นก่อน
  5. Claude ยิง query ตามแผน สรุปว่าเข้าข่าย privilege escalation แบบคลาสสิก เจอว่า source IP เป็น data center ในรัสเซียที่ VirusTotal ติดธง malicious สรุปว่าเหตุการณ์น่าจะถูกจำกัดวง และชี้ช่องโหว่ใน security posture พร้อม action item
  6. ผลสุดท้ายคือ investigation summary ที่รวมทุกขั้นที่ทำและสิ่งที่พบ ผู้พูดว่าเป้าหมายคือให้ผ่าน alert จำนวนมหาศาลได้แล้วยกเฉพาะเรื่องที่คนควรดู
  7. ผู้พูดเล่าว่าแผนไตรมาส 4 ตั้งไว้ว่า suppression engine ใช้ 1-2 เดือน แต่พนักงานใหม่คนหนึ่งทำเสร็จในหนึ่งสัปดาห์ เพราะ Claude Code อธิบายได้ว่าระบบตั้งอย่างไร ทำงานอย่างไร
  8. ผู้พูดมองว่าตัวเองขยับจาก practitioner ไปเป็นแนว researcher เพราะได้ทดลองวิธีประมวลข้อมูลปริมาณมหาศาลที่เคยแค่จินตนาการ

ลำดับขั้นที่ทำในคลิป

  1. เปิด CLUE แล้วถามเป็นภาษาธรรมชาติ: developer ให้สิทธิ์ admin ตัวเอง ได้รับอนุญาตไหม ตรวจ credential compromise และสิ่งที่ทำหลังจากนั้น
  2. Claude ร่างแผนสืบสวน 6 ขั้น
  3. Claude ยิง query ผ่าน tool use ไปยังแหล่งข้อมูล แล้วรายงานข้อมูลที่ได้
  4. Claude สรุป verdict เบื้องต้น (privilege escalation) พร้อมเหตุผล และยิง query เพิ่ม เช่น lookup source IP
  5. ได้ investigation summary สุดท้าย: ขั้นที่ทำ ข้อค้นพบ และ action item เรื่องช่องโหว่

ตัวเลข / ข้อเท็จจริงที่ผู้พูดบอก

ตามที่ผู้พูดอ้างในคลิป ไม่ได้ยืนยันกับแหล่งอื่น

  • เครื่องมือ 5-6 ตัว และภาษา query 3-4 ภาษา ต่อการสืบสวนหนึ่งครั้งก่อนมี CLUE
  • เวลาสืบสวนแบบเดิม: อย่างน้อยสองสามชั่วโมง ถึงมากสุดสองสามวัน (กรณีง่าย)
  • แผนวางไว้ suppression engine ใช้ 1-2 เดือน แต่พนักงานใหม่ทำเสร็จใน 1 สัปดาห์
  • แผนสืบสวนที่ Claude ร่างในเดโมมี 6 ขั้น

ส่วนใหญ่เป็นเพราะ Claude Code อธิบายให้ได้ (ประโยคต่อว่าระบบตั้งอย่างไร)

สิ่งที่นำไปทำต่อ

  • ให้ agent ต่อกับข้อมูลภายในที่เป็น context จริง ทั้ง data warehouse, Slack, code base ไม่ใช่แค่ log
  • ให้ Claude เขียนแผนสืบสวนก่อนลงมือ แล้วค่อยยิง query ตามแผน จะตรวจย้อนได้ง่าย
  • ออกแบบเครื่องมือให้ตรงกับงานของ analyst หน้างาน แทนที่จะให้ analyst ไปปรับตัวเข้ากับเครื่องมือ
  • ใช้ Claude Code เป็นตัวช่วย onboard คนใหม่เข้า code base ของระบบ detection

ข้อควรระวังในสรุปนี้

  • ชื่อและตำแหน่งผู้พูดมาจากคำอธิบายคลิป ไม่ได้ยินแนะนำตัวใน transcript
  • transcript เป็น YouTube auto-caption ผู้พูดสะกด Claude Code เป็น cloud code ในต้นฉบับ แก้เป็น Claude Code ตามบริบท และ CLUE สะกดในเสียงเป็น Clue
  • เดโมใช้ข้อมูลตัวอย่าง ผู้พูดย้ำว่าไม่ใช่ข้อมูลภายในจริง
  • ตัวเลขเวลา (ชั่วโมงเป็นนาที, 1-2 เดือนเป็น 1 สัปดาห์) เป็นข้ออ้างของผู้พูด ไม่มีหลักฐานแนบในคลิป
  • คำอธิบายคลิปบอกว่าใช้ Claude Sonnet และ Opus แต่ผู้พูดไม่ได้พูดถึงโมเดลใน transcript
