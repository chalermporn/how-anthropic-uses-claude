How Anthropic uses Claude ทุกคลิปสรุปรวม

#03 · Claude Cowork · 3:35

ทำ weekly metrics review ด้วย Cowork: Claude เตรียมตัวเลข คนเป็นคนกำหนดเรื่องเล่า

Claude Cowork for marketing ops

ผู้พูด: Ian (marketing ops and analytics (ตามที่แนะนำตัวในคลิป ไม่ได้ยินชื่อบริษัท แต่คลิปอยู่ในซีรีส์ของ Anthropic))

เหมาะกับ: ทีม ops หรือ analytics ที่ทำรายงานซ้ำทุกสัปดาห์ และอยากทำให้กระบวนการเป็นมาตรฐานแชร์ข้ามทีมได้

Ian ทำ metrics review รายสัปดาห์ (เอกสารเต็มสำหรับทีมมาร์เก็ตติ้ง กับสไลด์เดียวสำหรับผู้บริหาร) โดยแปลงขั้นตอนเป็น skill ใน Cowork ให้ Claude ดึงและตรวจตัวเลข ส่วนคนตัดสินว่าจะเล่าเรื่องอะไร เพราะขั้นตอนอยู่ใน skill จึงรันซ้ำได้เหมือนเดิมทุกสัปดาห์และแชร์ให้ทีมได้

A marketing ops analyst turns the weekly metrics review into Cowork skills: Claude gathers and verifies numbers, the human steers the narrative, and the skill makes the process repeatable and shareable.

ประเด็นสำคัญ

  1. งานเดิมคือดึงข้อมูลจากราว 6 แหล่งมาทำ metrics review ทุกสัปดาห์ เป็นเอกสารเต็มสำหรับทีมมาร์เก็ตติ้ง และสไลด์เดียวสำหรับผู้บริหาร
  2. กระบวนการแตกเป็น connectors กับ 3 skills: เตรียม review, proofread, และจัดการ action items รวมกันแล้วรันซ้ำแบบเดียวกันทุกสัปดาห์และแชร์ทีมได้
  3. ทุกเย็นวันอาทิตย์ scheduled task อ่าน review สัปดาห์ก่อนกับ transcript ประชุม เช็ก Slack ว่าทีมขายโฟกัสอะไร query warehouse แล้วทิ้งโฟลเดอร์ตัวเลขกับข้อเสนอ focus area ไว้ให้
  4. เช้าวันจันทร์ Ian เปิด Cowork ดู takeaways แล้วตัดสินเอง เพราะ Claude ดึงตัวเลขเก่ง แต่เรื่องที่จะเล่าเป็นการตัดสินใจของคน เช่นสัปดาห์นี้เป็นช่วงต้นไตรมาส จึงโฟกัสแผน Q2 แล้วโยน QBR doc ให้ Claude
  5. ถ้ามีอะไรไม่ตรงกัน skill ให้ Claude flag และถามแทนการเดา ตัวอย่างคือทีมขายจัดโครงสร้างใหม่ ทำให้รายงานไม่ตรงกับของทีมขาย Claude แสดงช่องว่างแล้วถามว่าจะจัดการอย่างไร Ian เลือกตามทีมขาย
  6. skill proofread ตรวจว่าทุกตัวเลขในร่างย้อนกลับไปที่แหล่งข้อมูลที่ verify แล้ว
  7. ร่างแรกมีแค่ตารางตัวเลขกับ headlines ให้ตรวจ outline ก่อน แล้วค่อยสั่งขยาย skill เติมรายละเอียดและตัวอย่าง โดยไม่แตะ headlines ที่ตกลงกันแล้ว
  8. พอสั่ง ship it Claude ทำเอกสารฉบับทีม เขียนข้อความลง Slack channel สร้างงานติดตามเป็น task ใน Asana (ASR เขียนว่า sauna) และสร้างสไลด์ผู้บริหารจากข้อมูลและเรื่องเล่าชุดเดียวกัน (อะไรเปลี่ยน ทำไม ควรทำอะไร) ปิดท้ายด้วยการถาม Claude ว่าสัปดาห์นี้เรียนรู้อะไรที่ควรเข้า skill เช่นโครงสร้างทีมขายใหม่และการแก้ของ Ian ถูกบันทึก Claude อัปเดต skill แล้วแชร์ให้ทีมรันได้ผลเหมือนกัน

ลำดับขั้นที่ทำในคลิป

  1. เย็นวันอาทิตย์: scheduled task อ่าน review สัปดาห์ก่อน + transcript ประชุม เช็ก Slack ที่ทีมขายโฟกัส query warehouse แล้วทิ้งโฟลเดอร์ตัวเลขและ focus area ที่แนะนำ
  2. เช้าวันจันทร์: เปิด Cowork ถามว่าการเตรียมเป็นอย่างไร ดู takeaways และ focus ที่แนะนำ
  3. ผู้ใช้ตัดสินโฟกัส (ตัวอย่าง: แผน Q2) แล้วใส่ QBR doc พร้อมบอกว่าให้นำด้วยเรื่องอะไร
  4. Claude flag จุดที่ข้อมูลไม่ตรง (เช่นทีมขายปรับโครงสร้าง) และถามว่าจัดการอย่างไร ผู้ใช้เลือกตามทีมขาย
  5. skill proofread ตรวจว่าทุกตัวเลขย้อนกลับไปแหล่งข้อมูลที่ verify แล้ว
  6. ร่างแรก: ตารางตัวเลข + headlines ผู้ใช้ตรวจ outline
  7. สั่งขยาย: skill เติมรายละเอียดและตัวอย่างโดยคง headlines เดิม
  8. สั่ง ship it: ได้เอกสารฉบับทีม ข้อความ Slack และ follow-up เป็น task
  9. Claude สร้างสไลด์ผู้บริหารจากข้อมูลและเรื่องเล่าเดียวกัน
  10. ถาม Claude ว่าสัปดาห์นี้เรียนรู้อะไรที่ควรเข้า skill แล้วให้ Claude อัปเดต skill ก่อนแชร์ทีม

ตัวเลข / ข้อเท็จจริงที่ผู้พูดบอก

ตามที่ผู้พูดอ้างในคลิป ไม่ได้ยืนยันกับแหล่งอื่น

  • ข้อมูลเคยต้องดึงจากประมาณ 6 แหล่ง ("half a dozen places")
  • 3 skills: เตรียม review, proofread, จัดการ action items
  • scheduled task รันเย็นวันอาทิตย์ แล้ว Ian ใช้เช้าวันจันทร์
  • ผลลัพธ์ 2 ชิ้นต่อสัปดาห์: เอกสารเต็มสำหรับทีม + สไลด์เดียวสำหรับผู้บริหาร

ประโยคเด่น (ต้นฉบับ)

“Together, the skills capture the process so I can run it the same way each week and share the process with the team.”

skills เก็บกระบวนการไว้ ทำให้รันเหมือนเดิมทุกสัปดาห์และแชร์ให้ทีมได้

“when something doesn't line up, Claude flags it and asks questions instead of guessing”

เมื่อมีอะไรไม่ตรงกัน Claude จะ flag และถามคำถามแทนการเดา

“I drop in the week's contacts, Claude verifies the data”

ผมใส่ context ของสัปดาห์ Claude ตรวจข้อมูลให้ (ASR เขียน contacts น่าจะเป็น context)

สิ่งที่นำไปทำต่อ

  • แปลงรายงานรายสัปดาห์เป็น skill แยกตามหน้าที่ (เตรียม, proofread, action items) แล้วรันซ้ำได้เหมือนเดิม
  • ให้ Claude flag และถามตอนข้อมูลขัดกัน ไม่ใช่เดาเอง คนเก็บอำนาจตัดสิน narrative ไว้
  • ทำตามลำดับ headlines ก่อน แล้วค่อยขยาย เพื่อล็อกสาระก่อนเติมรายละเอียด
  • ปิดทุกรอบด้วยคำถามว่าเรียนรู้อะไร แล้วเขียนกลับเข้า skill ให้กระบวนการดีขึ้นทุกสัปดาห์

ข้อควรระวังในสรุปนี้

  • Transcript เป็น YouTube auto-caption สะกด Cowork เป็น "Co-work" และ "Claude code work" ตอนท้าย ซึ่งน่าจะหมายถึง Claude Code หรือ Cowork ฟังไม่ชัดว่าหมายถึงอะไร
  • "sauna task" น่าจะเป็น Asana task (เดาจากบริบท) และ "contacts" น่าจะเป็น context ไม่ได้ยืนยัน
  • ไม่มีตัวเลขเวลาที่ประหยัดหรือผลลัพธ์เชิงปริมาณ ทั้งหมดเป็นการเล่าแบบเดโม
  • ผู้พูดแนะนำตัวเป็น Ian ในสายงาน marketing ops and analytics ไม่ได้ยินนามสกุลหรือชื่อบริษัท
  • คำอธิบายคลิประบุว่า Claude gathers and verifies numbers แต่ตัวคลิปไม่ได้แสดงวิธีที่ Claude verify นอกจากพูดว่า "traces back to a verified data source"
