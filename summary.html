ทุกคลิป · สรุปรวม

แปดคลิปสั้นเล่าเรื่องเดียว: คนนอกสายวิศวกรรมแปลงงานซ้ำเป็น skill และเครื่องมือของตัวเอง ส่วนคนยังเป็นผู้อนุมัติ

เพลย์ลิสต์ How Anthropic uses Claude มี 8 คลิป คลิปละ 2–4 นาที ผู้พูดเป็นพนักงาน Anthropic เล่างานของตัวเอง ตั้งแต่ GTM, กฎหมาย, มาร์เก็ตติ้ง, ขาย, security, product engineering ไปจนถึง PM ครึ่งหนึ่งใช้ Claude Cowork ผ่าน skill กับ scheduled task อีกครึ่งใช้ Claude Code หรือ API สร้างเครื่องมือเอง

หน้านี้สรุปเป็นภาษาไทยจาก transcript อัตโนมัติ ตัวเลขประหยัดเวลาทุกตัวเป็นคำประเมินของผู้พูดเอง และคลิปเป็นเนื้อหาที่ Anthropic ทำเพื่อเล่าการใช้งานของตัวเอง ใช้เป็นตัวอย่างรูปแบบการใช้ ไม่ใช่ benchmark

1. เริ่มจากงานซ้ำที่เจ็บจริง

อีเมลลูกค้า 600–700 บัญชี (#01), metrics review รายสัปดาห์ (#03), การเตรียมและตามงานประชุมลูกค้า (#04), การทำโฆษณาหลายแบบ (#08) ทุกเคสเริ่มจากงานเล็กที่ทำซ้ำ แล้วค่อยแปลงเป็นเครื่องมือ #08 แนะนำตรงๆ ให้เริ่มจากงานซ้ำที่อธิบายปัญหาได้ชัด

  • #01: ตอนเป็น AE ดูแลลูกค้าราว 600–700 บัญชี ตอบอีเมลถึง 2–3 ทุ่ม จึงสร้างตัวร่างอีเมลขึ้นมา
  • #08: นักการตลาดที่ไม่เคยเขียนโค้ดเริ่มจากงานทำโฆษณาซ้ำๆ แล้วสร้าง Figma plugin

2. เก็บขั้นตอนเป็น skill แล้วแชร์ทีม

#03 และ #04 ห่อขั้นตอนเป็น skill ให้รันซ้ำได้เหมือนเดิมทุกสัปดาห์และแจกเพื่อนร่วมทีม #02 ใช้ skill /brief กับ scheduled task ตอนเช้า ฝั่ง Cowork ทั้งสามคลิปจึงเป็นเรื่องของการทำให้ขั้นตอนเป็นสมบัติของทีม ไม่ใช่ของคนเดียว

  • #03: 3 skills (เตรียม review, proofread, action items) รันทุกเย็นวันอาทิตย์ แล้วแชร์ให้ทีม
  • #04: account strategy builder และ call transcript processor เป็น skill ที่ใช้ซ้ำทุกบัญชี

3. ต่อข้อมูลที่ทีมมีอยู่ ไม่ใช่ให้โมเดลเดา

พลังของ agent ในทุกเคสมาจากการต่อเข้าแหล่งข้อมูลจริง: Slack, Gmail, Jira (#02), Salesforce กับ data warehouse (#04), data warehouse และ code base ภายใน (#05), Playwright MCP (#06), BigQuery MCP (#07)

  • #07: PM ถามข้อมูลผลิตภัณฑ์ผ่าน BigQuery MCP ที่ทีม data science ตั้งไว้ โดยไม่ต้องเขียน SQL
  • #06: ต่อ Playwright MCP ให้ Claude เปิดแอป ดูผล แก้ และวนทดสอบเอง

4. คนยังอนุมัติปลายทางทุกเคส

#02 ทุกข้อใน brief เช็กกลับต้นฉบับได้ก่อนตอบ, #04 ข้อความตามลูกค้ารออนุมัติก่อนส่ง, #03 คนเป็นคนกำหนด narrative, #05 Claude วางแผนและยิง query แต่คนยังสืบสวนต่อ รูปแบบนี้ตรงกับหลัก verification-first

  • #04: action items, Slack ภายใน และข้อความตามลูกค้า รออนุมัติก่อนส่งทั้งหมด

5. ไม่ต้องเขียนโค้ดมาก่อน

#01 และ #08 ผู้พูดบอกว่าไม่เคยเขียนโค้ด, #07 PM ถามข้อมูลโดยไม่เขียน SQL, #06 backend engineer เข้า codebase frontend ที่ไม่คุ้น ข้อควรระวังคือหลักฐานในคลิปเป็นเดโมสั้นๆ ไม่ใช่ผลวัดในงานจริง

  • #08: โชว์เฉพาะ plugin ที่เสร็จแล้ว ไม่ได้โชว์ตอนสร้างด้วย Claude Code

6. เวลาที่เหลือย้ายไปงานคิด

#06 ผู้พูดบอกว่าเวลาที่เหลือเอาไปคิดระดับระบบและ trade-off มากขึ้น #07 เป้าหมายคือให้ PM มีเวลากับกลยุทธ์ การคุยลูกค้า และการตัดสินใจ ทั้งสองเป็นคำบอกเล่าของผู้พูด

    ควรดูคลิปไหนก่อน

    • ทีมขาย / GTM: เห็นรูปแบบ skill เตรียมประชุมและตามงานหลังประชุม กับเคส AE ที่สร้างตัวร่างอีเมลเอง (คลิป #01, #04)
    • ทีมกฎหมาย / มาร์เก็ตติ้ง / ปฏิบัติการ: ตัวอย่าง Cowork + scheduled task + skill ที่คนยังตรวจต้นฉบับได้ (คลิป #02, #03, #08)
    • วิศวกร / security: ใช้ Claude Code ต่อ MCP และข้อมูลภายในให้ agent วางแผนและสืบสวนเอง (คลิป #05, #06)
    • PM: ดึงข้อมูลผ่าน MCP โดยไม่เขียน SQL และขยาย test case ของ evals (คลิป #07)

    ข้อสังเกต / ที่ยังไม่ชัด

    • ตัวเลขประหยัดเวลาทุกตัวเป็นคำประเมินของผู้พูดเอง ไม่มีหลักฐานวัดในคลิป
    • เดโมในคลิป 5 และ 7 ใช้ข้อมูลตัวอย่าง/สังเคราะห์
    • คลิป 2 ผู้พูดบอกว่ามี 5 รายการงานเช้า แต่แจกแจงได้ 4
    • ชื่อผู้พูดบางส่วนมาจากคำอธิบายคลิป ไม่ได้ยินแนะนำตัวในเสียง
